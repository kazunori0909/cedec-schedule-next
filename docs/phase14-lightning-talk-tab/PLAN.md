# Phase 14: ライトニングトークタブ

## 課題

CEDEC 2026 から、公式タイムテーブルにライトニングトーク（以下 LT）の情報が載るようになった。
ただし他のセッションと扱いが異なり、**LT は「枠」単位でしか時間割に現れない**。

- 公式タイムテーブル上は `CEDEC Lightning 2026　第1会場　1日目`（12:30-13:00）という
  30 分の枠が 1 セッションとして置かれているだけで、個々の LT 講演は表示されない
- 個々の講演（各 6 分）は枠の詳細ページに一括で列挙されている
  （例: `https://cedec.cesa.or.jp/2026/timetable/detail/s69e879574138e/`）
- 2026 は 3 日 × 2 会場 = 6 枠、講演は合計 29 件

結果として、本サイトの Day1〜Day3 タブでは「LT 枠がある」ことしか分からず、
どんな講演があるのかを見られない。

## 方針

Day1〜Day3 のタブに加えて **LT タブ**を追加し、行＝時刻・列＝`Day1-1`〜`Day3-2`（日 × 会場）の
横断タイムテーブルとして全日程の LT 講演を一覧表示する。

### データ取得: 公式 timetable.json の `children` を使う（詳細ページのクロールはしない）

当初「タイムテーブルから詳細ページのリンクを辿って LT セッションページを走査する」案を検討したが、
調査の結果**その必要はない**ことが判明した。

すでに取得済みの `web_data_original/{year}/timetable.json` において、LT 枠の親ポストは

- `format_id: 22`（= `FORMAT_MAP` の「ライトニングトーク」）
- `children: RawPost[]` に個々の LT 講演を保持

という構造を持つ。子ポストは `title` / `category_id` / `subcategory` / `speakers` /
`held_at_as_child`（開始時刻）を備えており、必要な情報は**すべて揃っている**。
現状の `parseFormat2025Json` が `children` を読み捨てているだけで、追加のネットワーク取得は不要。

| 案                                     | 採否 | 理由                                                                |
| -------------------------------------- | ---- | ------------------------------------------------------------------- |
| A. 詳細ページ HTML をクロールして解析  | ❌   | 6 枠分の追加リクエストと HTML パーサーが必要。公式の DOM 変更に弱い |
| B. timetable.json の `children` を展開 | ✅   | 追加取得ゼロ・既存 JSON 方式の延長・構造化済みで年度間の差異に強い  |

### 終了時刻の導出

子ポストは `end_time: null` のため、開始時刻から導出する。

1. 同一枠内の子を開始時刻順に並べ、**次の講演の開始時刻**を終了時刻とする
2. 最後の 1 件は `min(開始 + 標準枠長, 親の end_time)`。標準枠長は開始間隔の最頻値（2026 は 6 分）

単純に「最後の 1 件は親の end_time」とすると、講演が枠の定員より少ない回
（2026 Day3 第1会場は 4 件のみ）で最後の講演が 12:48〜13:00 に伸びてしまうため、
最頻値によるクランプを入れる。

### 出力先: `schedule.json` に `lightning_talks` を新設

LT 講演を既存の `sessions[]` に混ぜず、**独立した配列 `lightning_talks: Session[]`** として出力する。

- 混ぜた場合、Excel 出力・CEDiL 紐付け・カテゴリフィルター・お気に入り・Day タブの
  部屋カラム生成という**全消費側に除外条件を足す**必要があり、漏れたときの影響が大きい
- 型は `Session` をそのまま再利用する（`day` = "1"〜"3"、`room` = "1"/"2" で列を導出できる）
- LT 枠の親ポストは**従来どおり `sessions[]` に残す**。Day タブで「この時間に LT がある」ことが
  分かる状態を維持する

`detail_url` は空文字とする（個々の LT 講演に固有の詳細ページは存在せず、
枠の詳細ページへのリンクも不要との判断）。

### 年度別設定は追加しない

`SCHEDULE_SETTING` には何も追加せず、**`lightning_talks` が空でなければ LT タブを出す**という
データ駆動の分岐にする。会場数が 3 に増えても、LT が 1 日だけでも、
`cedil_tag_no` のような手動追記なしで追従できる。

### 表示: 可変時間軸

現在のテーブルは `MIN_MINUTES = 5` の固定グリッドで時刻行を生成しており、
`buildMatrix` は `timeIndex.get(開始時刻)` が引けないセッションを**黙って捨てる**。
LT は 6 分刻み（12:30 / 12:36 / 12:42 …）のため、このままでは大半が表示されない。

対策として LT タブは、**実際に出現する開始・終了時刻の和集合をソートしたものを時刻行**とする。

```
12:10, 12:16, 12:22, 12:28, 12:30, 12:34, 12:36, 12:40, 12:42, 12:48, 12:54, 13:00
```

Day2 は 12:10-12:40、Day1/Day3 は 12:30-13:00 と開催時間が異なるが、
和集合を取ることで 1 つの時間軸に全日程を並べられる。

あわせて `buildMatrix` の rowSpan 計算を、`MIN_MINUTES` 割り算から
**「終了時刻の行インデックス − 開始時刻の行インデックス」**に一般化する。
既存の 5 分グリッドでは終了時刻が必ずグリッド上に存在する（`getTimeRange` の max が
セッション終了時刻の最大値のため）ので、通常テーブルの描画結果は変わらない。

### タブの状態管理

`yearStates[year].dayIndex` に LT を表す番兵値 `LT_DAY_INDEX = -1` を追加する。

- 既存の永続化値（0〜2）と衝突せず、`getDateList` / `findTodayDayIndex` の
  日付インデックスとも取り違えない
- LT データがない年度で `dayIndex === -1` が復元された場合は 0 にフォールバックする

## 決定事項ログ

### 2026-07-23: データ取得方式

- 詳細ページのクロールは**行わない**。`timetable.json` の `children` に必要な情報が
  すべて含まれていることを実データで確認したため（2026: 6 枠 / 29 講演）
- **理由**: 追加のネットワーク取得と HTML パーサーが不要で、公式サイトの DOM 変更にも影響されない

### 2026-07-23: 年度別設定を追加しない

- `SCHEDULE_SETTING` に LT 関連の設定項目を追加せず、生成された `lightning_talks` の
  有無で LT タブの表示を切り替える
- **理由**: 新年度追加時の手動作業を増やさない。会場数・開催日数の変化にも自動追従できる

### 2026-07-23: LT 講演は `sessions[]` と分離する

- `schedule.json` のトップレベルに `lightning_talks: Session[]` を新設する
- **理由**: `sessions[]` に混ぜると Excel 出力・CEDiL 紐付け・フィルター等の全消費側に
  除外条件が必要になり、漏れたときに Day タブへ 29 件の LT が紛れ込む

### 2026-07-23: セッション詳細ページへのリンクは付けない

- LT 講演セルは `detail_url` を空にし、タイトルをプレーンテキストで表示する
- **理由**: 個々の LT に固有の詳細ページが存在しない（枠単位のページしかない）ため

### 2026-07-23: LT 枠の親セッションは Day タブに残す

- 「CEDEC Lightning 2026　第1会場　1日目」は従来どおり Day タブに表示し続ける
- **理由**: Day タブだけを見ている利用者にも「この時間に LT 枠がある」ことが伝わる状態を保つ

### 2026-07-23: LT タブでもお気に入りの★は消さない

- `SessionCell` に表示切り替えの prop は追加せず、★ は全タブで表示する。
  LT タブで隠すのは `FavoriteToggle`（お気に入りモードの絞り込み）だけとする
- **理由**: ★ の登録・解除は `favorites`（セッションID キー）で LT でもそのまま機能する。
  Day1〜3 に依存するのは絞り込み側のみで、★ を消すには「タブ単位の判断」を
  セル単位の prop としてバケツリレーする必要があり、割に合わない

### 2026-07-23: Phase 13 の CEDiL 除外を解除する

- `generate_cedil.ts` の `LIGHTNING_TALK_RE` による除外を撤去し、LT 資料も `cedil.json` に含める。
  `useScheduleData` の突き合わせ対象に `lightning_talks` を追加する
- **理由**: Phase 13 で除外したのは紐付け先のセッションが存在しなかったため。
  LT 講演がデータ化された今は、既存のタイトル一致ロジックがそのまま機能する
- **実測**: 2026 で CEDiL 14 件中 3 件が LT。14 件すべてが正しいセッションへ紐付き、
  懸念していた「短い LT タイトルの通常セッションへの誤ヒット」は発生しなかった
