# Phase 8: 依存パッケージの安全なアップデート

## 課題

1. 依存パッケージに未適用の更新が溜まっており、脆弱性・最新版の有無を把握できていない。
2. TypeScript 7.0 が正式リリースされたため、移行可否を検証したい。
3. 更新の可否をエコシステム（周辺ツール）の対応状況と実測で判断したい。

## 方針

- レンジ内で安全に上げられるパッチ／マイナー更新はまとめて適用する（案A・採用）。
- メジャー更新は peer 依存だけで判断せず、検証ブランチで実際に導入して
  lint / tsc / test / build を回し、実測で可否を決める。
- 上流（周辺ツール）が未対応でクラッシュするものは見送り、再訪の合図を記録する。

### 見送ったもの（上流未対応・実測でクラッシュ）

- **TypeScript 7.0**: ネイティブ（Go）版で JS コンパイラ API が刷新され、`typescript-eslint`
  が実 API を参照して lint クラッシュ／Next 16 ビルド失敗。回避には TS6 ブリッジ
  （`@typescript/typescript6`）＋ Next canary の `useTypeScriptCli` が必要で、公開サイトに
  canary を常用するリスクが釣り合わないため見送り。
- **ESLint 10**: `eslint-config-next` が内包する `eslint-plugin-react@7.37.5`（最新）が
  ESLint 10 で削除された `context.getFilename()` を呼びクラッシュ。peer も `^9.7` 止まり。
- **@types/node 26**: 実行環境が Node 22 のため、型は 22 系に合わせるのが正。
- **uuid（exceljs 経由の moderate）**: 前方修正がなく、該当 API 経路を踏まないため実害ほぼゼロ。

詳細な実測ログ・再訪の合図は [KNOWLEDGE.md](KNOWLEDGE.md) を参照。
