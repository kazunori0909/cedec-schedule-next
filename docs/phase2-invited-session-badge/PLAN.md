# Phase 2: 招待セッション表示（Room横に招待バッジ）

## 課題

1. CEDEC公式の種別マスタ（`scripts/parsers/cedec_taxonomy.ts` の `TYPE_MAP`）には
   招待(2)・特別招待(5)・団体招待(6)・海外招待(7) という「招待セッション」を示す種別が存在するが、
   `Session` 型にはこの情報を保持するフィールドがなく、パース時点で判定に使われた後は破棄されている。
   - JSON方式（2025〜）: `scripts/parsers/format_2025_json.ts` が `post.type_id` を分野なし時の
     カテゴリフォールバック（`TYPE_AS_CATEGORY = {3,4,9}`）にのみ使い、それ以外は捨てている。
   - HTML方式（〜2024）: `format_2020.ts` / `format_2023.ts` が `ses-type` から種別名を読むが、
     `EXCLUDED_SESSION_TYPES = ["公募", "招待"]` により「招待」は判定にすら使われず捨てられる。
2. 現状UIでは、招待セッションかどうかを一見して判別する手段がない
   （カテゴリバッジ枠を使うと通常の分野バッジと混同しやすいため、別枠での表示が必要）。

## 方針

- **対象年度**: 2025年以降のJSON方式のみを対象とする。HTML方式（〜2024年）のパーサーは変更しない。
- **対象種別**: `type_id` が 招待(2)・特別招待(5)・団体招待(6)・海外招待(7) のいずれかであるセッションを
  「招待セッション」として扱う。表示文言はいずれの種別でも一律「招待」とする。
- **データ設計**: `Session` 型（`src/types/schedule.ts`）に `is_invited?: boolean` を追加する。
  `RawSession`（`scripts/lib/session.ts`）にも同様に追加し、`buildSession()` の引数で受け取る。
  `format_2025_json.ts` で `post.type_id` が対象種別集合に含まれるかを判定して設定する。
- **UI設計**: カテゴリバッジ（`CategoryBadge`）とは別に、`SessionCell.tsx` の
  「Room: 」表示の右側に「招待」バッジを配置する（画像添付イメージ: `Room: 1 [招待]`）。
  カテゴリ枠と混在させず、Room行にインラインで並べることで一見して判別できるようにする。

## 決定事項ログ

### 2026-07-06: 対象範囲を確定

- 対象年度は2025年以降のJSON方式のみとする。HTML方式（〜2024年）は変更しない。
  理由: HTML方式は `EXCLUDED_SESSION_TYPES` によりそもそも種別を判定に使っておらず、
  対応するには各年度パーサーの改修が必要になり作業量が増えるため、まずはJSON方式のみに絞る。
- 「招待」として扱う種別は 招待・特別招待・団体招待・海外招待 の4種すべてとする。
  バッジ文言はいずれも「招待」に統一する。
