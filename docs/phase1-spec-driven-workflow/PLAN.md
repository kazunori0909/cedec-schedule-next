# Phase 1: プチ仕様駆動開発の導入

## 課題

1. 開発作業の背景・決定事項・経緯が会話やコミットメッセージに散在し、後から追いにくい。
2. 他プロジェクトで運用していた「プチ仕様駆動開発」用スキル（`phase-new` / `phase-compress`）を
   `.claude/skills/` に移植したが、前提となる `docs/` 構成（フェーズ記録・`phases.md`）が
   このプロジェクトには存在しなかった。

## 方針

- `docs/README.md` を新規作成し、「開発フェーズ記録」テーブルを設置する。
- 以降、非自明な設計判断を伴う作業は `docs/phase<N>-<slug>/` にフェーズとして記録し、
  `PLAN.md`（設計判断とその理由）・`TASKS.md`（作業チェックリスト）で管理する。
  実機調査・外部サービス調査で気づきが出た場合は `KNOWLEDGE.md` を追加する。
- 完了済みフェーズは `phase-compress` スキルで `docs/phases.md` に圧縮する（ユーザー指示時のみ）。
- 本フェーズ（Phase 1）は運用そのものの立ち上げであり、上記の型を実践する第一弾とする。

## 決定事項ログ

### 2026-07-04: プチ仕様駆動開発を本プロジェクトに導入

- 他プロジェクトから移植した `phase-new` / `phase-compress` スキルをこのプロジェクトでも
  使えるよう、`docs/README.md` を新規作成しフェーズ管理を開始する。
- スキル内の記述にあった移植元プロジェクト固有のルール参照（CLAUDE.md の特定セクション・
  SECURITY.md §9 等、このプロジェクトには存在しないもの）は削除済み（Phase 1 着手前の下準備）。
- 作業中、`docs/README.md`・`docs/phases.md` に無関係な別プロジェクト（請求書自動化ツール）の
  内容が誤って存在しているのを発見し、ユーザー確認の上で削除してから本フェーズの雛形を作成した。
