# Phase 16: テスト整理・ドキュメント同期・重複排除リファクタリング

## 課題

Phase 9〜15（CEDiL フェッチ抑止・Live配信予定バッジ・LTタブ・PHP エンドポイント）で機能追加が
続いた結果、テスト・ドキュメント・実装のそれぞれに実態とのズレが溜まっている。

1. **テストの過不足**
   - 最近追加した機能（Live配信予定バッジ、キャンセル表示、`cedil_tag_no` 未設定時のフェッチ抑止、
     LT データが無い年度での LT タブフォールバック）に回帰テストが無い。
   - 参照ゼロの関数（`getSessionTitle`）が残っている。
2. **ドキュメントの更新漏れ**
   - `AGENTS.md` のフォルダ構成が `src/__tests__/`（Phase 6 で廃止）のまま。開発コマンドにテスト系が無い。
   - Phase 14 の LT タブが `README.md` / `AGENTS.md` に一切反映されていない。
   - `README.md` の年度別設定表に `room_overrides`（2025 で使用中）が無い。`.claude/skills/` の一覧も古い。
   - `SECURITY.md` の `dangerouslySetInnerHTML` 例外の記述が実態（`cedec.ts` の `events` / `dev_night`）と不一致。
     Phase 15 で追加した CEDiL 更新トークンの設定ファイルにも触れていない。
   - `docs/README.md` の Phase 4・8 が「進行中」のまま。
3. **重複・デッドコード**
   - `exportExcel.ts` がカラム・時刻軸の導出を手組みしており `buildScheduleViewModel` と重複。
   - カテゴリ色が `globals.css` / `categoryBadgeColors.ts` / `exportExcel.ts` の3箇所に分散。
   - ストアの `toggleHideSpec` / `toggleFavorite` が同型のロジック。
   - `col.roomName ?? col.name` の二重記述、内部専用関数の不要な `export` など。
4. **データ由来の描画不具合**
   - 2011 年データに `sub_category` の重複（`["GD","GD"]` 等）があり、React の key 衝突とバッジ二重表示が起きる。

## 方針

上記 1〜4 を1フェーズで片付ける。挙動を変えるのは 4 のみで、1〜3 は外形的な振る舞いを変えない。

- **テスト**: 「ライブラリの挙動を検証しているテスト」（Radix Sheet の ESC / オーバーレイ、Popover の
  外側クリック）は今回は**削除しない**。Phase 5 で自前実装から置き換えた経緯の回帰防止として意図が
  読めるため、判断を保留する。不足しているテストの追加のみ行う。
- **ドキュメント**: 実装を正とし、ドキュメント側を実態へ寄せる。過去フェーズの `docs/phase*/` は
  当時の記録なので書き換えない。
- **カテゴリ色**: Tailwind はクラス名を静的に走査するため完全な動的生成はできない。
  `{ class, hex }` を1テーブルに束ねて「コード追加時に1箇所だけ直せばよい」状態にする。
  実データに存在しない `INT` は削除する。
- **sub_category 重複**: 生成側（パーサ）で dedupe する。表示側で毎回 dedupe するより、
  `schedule.json` の時点で正規化されているほうが Excel 出力など他の消費者にも効く。

## 対象外

いずれも本フェーズでは扱わず、[Phase 17](../phase17-cedil-config-excel-lt/) で対応した。

- ビルド出力（`out/cgi/generate_cedil.config.php`）に CEDiL 更新トークンの設定ファイルが混入する件。
- Excel 出力への LT シート追加（仕様判断が必要だったため）。

## 決定事項ログ

### 2026-07-30: お気に入りモードの会場表示バグを本フェーズで修正

- `roomName` の重複記述（`col.roomName ?? col.name`）を整理する過程で、お気に入りモードでは
  カラム名（"お気に入り 1"）がそのまま各セルの `Room:` 表示に流れていることが判明した。
  実機相当のレンダリングテストで確認したうえで修正した。
- `RoomColumn.roomName` の意味を「カラム内の会場が一意な場合の会場名」と定義し、
  混在するカラム（お気に入り）では `undefined` にしてセッション自身の会場（`getSessionRoom()`）を使う。
  会場リンク（`getFloorURL`）もカラムの会場が一意なときだけ張る。

### 2026-07-30: スコープの確定

- 指摘のうち「テストの過不足」「ドキュメント同期」「リファクタリング」「sub_category 重複」を実施し、
  トークン設定ファイルのビルド混入は保留とユーザーが決定。

  壊れていないことを示す価値を優先する。
